## 항목별 주의 (넣기 전에 볼 것)

- **M11 뒤 화면 물러남:**
  - 앱 뿌리를 scale하면 그 안의 `position: fixed`(하단 탭바, 토스트)가 같이 줄거나 기준이 바뀐다. 뿌리의 구조부터 본다.
  - 폰 업무 창은 `modals.jsx`의 `dc-rise` 길이다. M10·M12도 같은 창이다.
- **M14 성경 장 넘김:** `wordBible.jsx`에 이미 장 넘기기 제스처가 있는지 먼저 본다. 있으면 그 위에 '따라오기 + 도중 취소'만 얹는다.
- **M26 길게 눌러 확정:**
  - 확인 창 흐름이 바뀐다. 어느 동작에 쓸지는 **위험한 것만**(업무 삭제, 계정 합치기 같은 것)이다.
  - **버튼 글('길게 눌러 삭제' 등)은 새 화면 문구다.** 넣기 전에 표로 묻는다(CLAUDE.md).
- **S3 상단 바 물러남:** `layout.jsx`의 TopNav가 대상이다. 다붓이 입구 알약은 물러나지 않게 둔다.
- **C2·C7·C9 토큰 재구성은 크다.**
  - 한 번에 갈아엎지 않는다.
  - 먼저 C9(역할 토큰 이름 정리)와 C7(10단 표 문서화)로 지금 값을 표에 옮긴다.
  - 그다음 C2의 '세 값 → 계산'을 라이트·다크 값이 지금과 같게 나오는지 검사로 묶어 바꾼다.
  - themefit·handoff 대비 검사가 지킨다.
- **C3 따뜻한 회색:**
  - 지금의 자색 기운은 로그인 빛에 맞춘 예전 결정이다. 사용자가 2026-10-27에 이번 묶음 전체를 승인했다.
  - `--app-canvas · surface · line · ink-*` 값을 바꾸고 다크도 같이 바꾼다. 그림자 색조(`--app-shadow-*`의 46 36 80)도 같이 따뜻하게 맞춘다.
- **C10 모임마다 색조:** 색조를 어디서 가져올지(동아리 태그색, 순 색) 코드에서 먼저 찾는다. 없으면 새 칸이 필요하니 그때 묻는다.
- **C8 P3:** `@media (color-gamut: p3)`일 때 `--app-brand-grad`, 바탕 빛, 다붓이 색만 바꾼다.
- **D9 브라우저 기본 팝오버:**
  - `usePopover`·`ConfirmPopover` 전체를 갈아끼우는 일이라 위험하다.
  - 한 곳(예: 알림 판)에서 먼저 해 보고, 폰 사파리와 카카오 인앱에서 되는지 확인한 뒤 넓힌다.
  - 지원이 없으면 지금 길로 돌아가야 한다.
- **D4 빈도 사다리:** 표 한 장으로 감사한다. 자주 쓰는 동작의 모션을 줄이는 것이다. 사용자가 맞춘 값(예: 홈 등장)은 건드리기 전에 HANDOFF·PITFALLS에서 결정인지 확인한다.
- **D8 테마 얼룩:** `layout.jsx:184`에서 `dataset.theme`을 바꾸는 순간에만 전환을 끈다.
- **D11:** 한국어에는 `word-break: keep-all`과 같이 쓴다. 제목은 `text-wrap: balance`, 긴 본문은 `pretty`다.

## 지킬 것

- `CLAUDE.md` 그대로다.
  - 관련 스위트만 돌린다(전체 verify 금지).
  - 새 로직에는 검사 하나를 남기고, 일부러 되돌려 실패하는지 확인한다.
  - 커밋은 한국어로 쓰고 어시스턴트 줄을 넣지 않는다.
  - 새 화면 문구는 표로 먼저 묻는다. 안내 문구 줄은 넣지 않는다.
- **움직임:**
  - transform·opacity만 움직인다(위 승인 항목은 예외).
  - `prefers-reduced-motion`을 지킨다.
  - 시간·곡선은 `index.css` 토큰을 쓴다.
- **대비와 글자:** 대비는 4.5:1 이상이다. 10px 미만 글자는 쓰지 않는다. 12px 미만 글자에는 faint를 쓰지 않는다.
- **눈에 보이는 크롬 창을 함부로 띄우지 않는다**(사용자 지적 2026-10-27). 화면 확인은 검사 스위트(헤드리스)로 하고, 꼭 필요할 때만 Puppeteer를 쓴다.
- **진행 중 설명은 한국어로 짧게.** 바꾼 것마다 "그래서 뭐가 좋아지나"를 같이 말한다.
- 아티팩트를 고칠 때는 **같은 URL**에 한다. 새 주소를 만들지 않는다.

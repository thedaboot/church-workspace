# v2 설계 — 예배 · 순 · 말씀 · 동아리

2026-09-01 그릴링(요구사항 인터뷰)으로 사용자와 함께 확정한 설계입니다.
v2 회차 내내 **이 문서가 기준**입니다. 스펙 논쟁이 생기면 여기로 돌아옵니다.
구현 흐름은 HANDOFF §2(저장 자리 → 마이그레이션 → 코드 → 검사 → 문서)를 그대로 밟습니다.

## 0. 한 줄 요약

지금까지는 스태프 15명의 업무 도구였고, v2부터는 **청년 ~50명의 매일**(QT · 예배 ·
순 · 동아리)을 담는다. 기존 워크스페이스는 안쪽 구조 그대로 '업무' 영역으로 들어간다.

| 동아리 가입 신청 수락 | 그 동아리 리더 |

직분 구조(2026-09-05 · 0043으로 갱신): **교역자**(명단 속성 `is_pastor`, 연도 무관) · 연도별 다섯 —
**부장 · 회장 · 총무 · 리더순장 · 리더팀장**(`people_roles.role` = director/president/treasurer/lead_sunjang/lead_team,
화면 순서도 이 순서). 위 표의 '임원'은 이 다섯 값을 뜻한다 — `is_officer()`와 클라이언트 권한은 값이 아니라 "그 해 줄이
있는가"만 보고, 회장(`president`)·리더순장(`lead_sunjang`)만 값으로 갈린다. 옛 `officer`(임원)는 사라졌다.
순장·동아리장은 모임의 리더 지정에서 파생(별도 권한 테이블 없음). 그 밖의 직함은 `role_note` 자유 텍스트.
2026년 실제: 신효진 부장 · 양민혁 회장 · 조해리 총무 · 정민경 리더순장 · 조준환·박지호 리더팀장 · 임성빈 교역자.
기존 가입자 15명의 직분은 그대로 승계하고, 미가입자 명단은 회차 1 전에 사용자가 준다.

### 지키는 원칙 (기존 §7·§8에서 살아 있는 것)

- **랭킹·점수·배지·스트릭 금지**, 누가 누구와 견주는 구조 금지. 예시 앱의 '리더보드'는
  들여오지 않는다. QT 잔디가 허용되는 건 "나만 보는 나의 기록"이라서다.
- 순장에게 순원의 QT 현황·노트(공유 안 한 것)를 보여주지 않는다 — '안 한 사람이
  지목되는' 구조가 되기 때문(§7 카드 조회 추적을 뺀 같은 이유).
- 안내·힌트 문구는 먼저 물어보고 붙인다. 문구 톤은 §8 그대로.
- §7의 "순은 화면 축이 아니라 속성" 항목은 **이 문서로 대체**된다(사용자가 v2에서
  직접 다시 꺼냈다). 단 "순별 업무 보드를 만들지 않는다"는 그대로다 — 순은 목양 축이지
  업무 축이 아니다.

## 2. 데이터 (저장 자리 초안 — 회차 1에서 확정)

HANDOFF §2-1 기준: 카드처럼 언제나 같이 읽고 쓰는 것은 jsonb 컬럼, 따로 조회·집계할
것만 조인 테이블.

```
people            명단. id · name · birthday? · profile_id(→profiles, null 허용) ·
                  is_pastor · note · removed_at
people_roles      연도별 직분. person_id · year · role('회장'|'리더순장')
groups            모임. id · type('sun'|'club') · name · year(순만) · leader_person_id
group_members     group_id · person_id (순은 편성, 동아리는 가입)
club_applications group_id · person_id · status(대기/수락/거절)
group_meetings    동아리·순모임 일정. group_id · date · title? · attendance jsonb
services          예배. id · kind('sunday'|자유 이름) · date · status(draft|published) ·
                  title · passage_ref · preacher · roles jsonb(담당자) ·
                  songs jsonb(찬양) · notices jsonb(광고) · attendance_note
attendance        service_id · person_id · checked_by · created_at  (있으면 출석)
service_notes     예배 노트. service_id · profile_id · body · shared_to_sun
qt_schedule       date(pk) · passage_ref · label?   (시드 마이그레이션으로 채운다 — 0038)
qt_entries        date · profile_id · body · shared · created_at
bible_state       profile_id(pk) · last_ref · bookmarks jsonb
성경 본문          DB 아님 — public/bible/*.json (개역한글, 책 단위 청크, lazy load)
```

- RLS: 읽기는 승인 멤버 전체(예외 — `qt_entries`·`service_notes`는 본인 + 공유 범위).
  쓰기는 위 권한 표대로, 화면만이 아니라 **DB에서도** 막는다(0029 전례).
- 출석의 사람 축은 profile이 아니라 **person**이다. 가입 시 profile↔person을 잇는다.

## 3. 화면 (IA — 목업으로 확정)

### 모바일 하단 바: 홈 · 예배 · 말씀 · 모임 · 업무

- **홈** — 교회 생활 요약: 오늘의 QT · 이번 주 예배 · 내 업무 N건 · 내 순 소식 · 생일
- **예배** — 주보 목록(종류·연도 필터) → 상세(말씀 / 임사자 / 찬양 / 광고) ·
  권한자에게 작성·발행 · 출석 체크 · 내 예배 노트
- **말씀** — QT(기본 탭: 오늘 본문 → 묵상 기록 → 나눔 피드 · 내 잔디) |
  성경 읽기(리더 · 북마크 · 이어읽기)
- **모임** — 내 순(명단 · 출석 현황 · 공유된 예배 노트) · 동아리(목록 · 가입 신청 · 모임)
- **업무** — 누르면 **하단 바가 지금의 네 칸(프로젝트 · 내 업무 · 대시보드 · 팀)으로
  바뀐다**(모드 전환 — 기존 손 습관 보존, 겹 수 안 늘림). 맨 왼쪽 '홈으로'로 복귀.
  안쪽 화면은 지금 그대로.

### 데스크톱 상단 1줄

`홈 · 예배 · 말씀 · 모임 | 업무 대시보드 · 내 업무 · 일정` + 검색·종·설정.
2줄째 프로젝트 탭 줄은 워크 문맥에서 지금처럼. 모드 전환 없음(폭이 넉넉하다).

### 만들 때 주의

- 새 전역 화면은 `GLOBAL_MENUS`에 등록(안 하면 프로젝트 id로 오해 — §3),
  안에서 스크롤하면 `needsFullHeight`도.
- (끝남) 회차 2의 임시 진입로(전역 메뉴)는 회차 3에서 하단 바 A안으로 재편됐다 — §5.

## 4. 회차 (확정)

| 회차 | 내용 | 방식 |
|---|---|---|
| 1 · 기반 | 명단·모임·직분·계정연결 스키마 + 마이그레이션 + 명단 시드(사용자 제공) + 명단 관리 화면(멤버 화면 확장) + 개역한글 데이터 파이프라인 | 순차 (전부의 전제) |
| 2 · 세 줄기 | 예배 줄기(주보·출석·노트) ∥ 말씀 줄기(성경 리더·QT) ∥ 모임 줄기(순·동아리) | **Opus 5 에이전트 3개 병렬**, 완결된 세로 조각 |
| 3 · IA 재편 | 하단 바 5칸 + 업무 모드 전환 + 홈 화면 + 데스크톱 상단 | 순차 |
| 4 · 통합 검증 | 전체 스위트 + 새 검사 + HANDOFF·README·§7 갱신 | Fable 5 (분석·검증 통합) |

- 역할: **설계·검증 = Fable 5, 구현 = Opus 5** (excel-fidelity-loop의 일반화 —
  Fable 분석 → Opus 구현 → Fable 재검 → 푸시).
- **푸시 전에 사용자 확인**(사용자 지시 2026-09-01): 회차 작업이 끝나면 바로 푸시하지
  않고 로컬 dev 서버를 띄워 사용자가 먼저 본다. 확인 후에 푸시(=Vercel 배포).
  클라우드 경로 확인 부탁(§2-6)은 그대로.
- 새 로직에는 검사를 하나 남기고 일부러 되돌려 실패를 확인(§2-5). 새 스위트 후보:
  성경 데이터 정합(장·절 수), QT 본문표 파싱, 출석 집계, 주보 렌더, 내비 스모크 확장.
